住宅社區的平靜基礎設施

Calm infrastructure for residential communities — 連結社區，安居有序。管理員的作業系統，住戶的乾淨體驗。

值得信賴、專業、不浮誇。深藍調性，零廣告，狀態誠實。

Navy / CalmManager-First DensityWCAG AA 繁體中文（台灣）零廣告無漸層 · 純平塗

五大設計原則 — Design Principles (§1.1–1.5)

§1.1

平靜基礎設施

Calm Infrastructure

是基礎設施，不是娛樂。每個視覺決策都在降低認知負擔，而非爭奪注意力。大量留白、清晰層級、克制用色。無廣告是設計約束，不只是商業模式。

§1.2

管理員優先密度

Manager-First Density

Web 後台是專業作業工具。資料表單 fold 以上顯示 15–20 列、篩選即時可達、動作一鍵可達。漸進揭露：常用 20% 動作就地呈現。「井然有序、值得信賴」才對。

§1.3

住戶簡潔

Resident Simplicity

住戶不是付費方，卻是衡量指標。55 歲首次使用者不看說明就能完成領取。每畫面一個主要動作、底部固定導覽、推播先回答「我該做什麼」。

§1.4

透明賺取信任

Earned Trust Through Transparency

台灣住宅市場有信任赤字。隱私可見、狀態誠實（精確時間戳，不用模糊「處理中」）、絕不隱惡——失敗清楚顯示錯誤態，而非靜默失敗。

§1.5

台灣專業情境

Taiwanese Professional Context

主要買方是 45–65 歲主任委員。繁體中文為主、系統訊息用敬語「您」、保守視覺語言（無漸層、無到處的 pill、無 Gen-Z 色盤）。日期 2026年6月14日 / 06/14。

清空間與最小尺寸 — Clear Space & Minimum Size

清空間 = X

四周淨空 ≥ X（X = 圖標中單一房屋寬度）。主要/橫式組合四周留 X；純圖標留 ½ 屋寬；頁首受限處可降至 ½X，不得更小。淨空內不得放置文字或圖形。

XX

最小尺寸 — 數位

主要直式 ≥ 96px（低於改用純圖標）。橫式 ≥ 160px。純圖標 ≥ 24px（最小單元）。Favicon 用 linkju-mark.svg，16px 仍可辨識輪廓（節點圓點會合併，可接受）。

中文「連居」字級在任何組合中 不得小於 14px（CJK 最小可讀字級，design-system §3.3）。

最小尺寸 — 印刷

主要直式 ≥ 24mm。橫式 ≥ 32mm。純圖標 ≥ 8mm。App 圖標由系統規範縮放（iOS 29pt / Android 48dp 起）。

標誌承載辨識資訊的色彩對背景至少達 3:1（UI），字標達 4.5:1。brand-400 僅可用於深藍底，不得置於白底承載文字。

✅ Do

  • 使用提供的 SVG 原始檔，等比例縮放
  • 維持清空間與最小尺寸
  • 深色背景一律使用反白版
  • 單色印刷／傳真／蓋章使用單色（深藍）版
  • 雙色版只用在淺色背景
  • 圖標、中文字標、拉丁字標維持原組合鎖定 (locked-up)

❌ Don't

  • 不更改標誌顏色（不得換成紅、綠、黃、灰或任何非 brand 色）
  • 不加漸層、陰影、外光暈、描邊、3D、倒影
  • 不旋轉、不傾斜、不鏡像、不非等比拉伸
  • 不重新排列元素、不拆開「連居」與「Linkju」
  • 不替換字型、不以簡體渲染「連居」
  • 不把雙色版放在深藍底（對比不足，該用反白版）

04 — 字體

字體 Typography

繁體中文渲染規則 — CJK Rules

14px 下限

中文字最小 14px（logical px）。表格儲存格 14px 起，絕不為密度壓到 12px。12px 僅次要資訊（時間戳）可用。行高不低於 1.4。

敬語「您」

系統訊息、公告、報表對管委會/主委一律用敬語「您」，絕不用「你」。正式而不冷漠，呼應「鄰居」溫度。

tabular-nums 對齊計數

計數、金額、戶號用等寬數字對齊：

字重：內文 400、強調 500、僅 H1/H2 用 700。

06 — 元件

元件庫 Components

以真實 HTML/CSS 渲染的元件範例，全部消費 semantic token。一個畫面一個 primary 按鈕；danger 須伴隨確認對話框；一列一個 badge（urgent/逾期為正交維度可疊加）。

按鈕 Buttons

primary brand-600→hover brand-700 · 停用用「色」不用 opacity（disabled = brand-300）· danger 僅限不可逆破壞性動作，需確認對話框。

狀態徽章 Status Badges

待處理 處理中 已完成 草稿 已排程 緊急
「OPEN = amber 不是 grey」決議： 工單剛建立、尚未指派 (OPEN) 一律對映 status.pending＝琥珀 amber，廢除 grey-OPEN 對應。「未指派」是需要管理員行動的狀態，灰色會讓它在列表中視覺消失，違反 Manager-First Density。灰色只保留給真正非活躍、不需行動的狀態——公告草稿。工單沒有任何狀態用灰色。

逾期 danger overlay — 疊加，不取代狀態色

逾期是與工單狀態正交的維度。逾期時，狀態 badge 維持不變，紅色「逾期」chip 另外疊加在旁邊（Team B 決議：overlay，不是把狀態色換成紅色）。

07 — Trust & Anti-patterns

我們刻意避免什麼

以「透明賺取信任 (Earned Trust Through Transparency)」為核心，把兩大競品（智生活 / 中保好生活）的具體 UX 反模式，逐條對映到 Linkju 可被機械化檢查的設計守則。信任要靠透明賺取，不靠徽章宣稱。

競品陷阱來源 / 證據對映原則Linkju 守則 (guardrail)
廣告注入 + 付費才去廣告智生活 [已查證]§1.1 / §1.4任何畫面禁 banner／推廣卡／贊助內容／第三方廣告位（出現即退件）；禁「付費解鎖乾淨體驗」；通知分級不綁付費。
資安徽章宣稱 vs 實測落差（消基會 16 項未過）智生活 [已查證]§1.4不放無法驗證的「資安認證徽章」做信任裝飾；徽章須可點擊連到第三方報告才可放；隱私宣告完整、一鍵可達；敏感操作須二次確認。
通知濫發 + 一刀切設定智生活 [已查證]§1.3 / §1.4通知分級可訂閱（緊急公告不可關／一般公告／包裹／工單）；無「行銷推播」類別（無廣告）；推播文案前置「要做什麼」。
功能埋藏 / 退步式改版智生活 [已查證]§1.3 / §1.2住戶端固定 4 tab，核心動作距首頁最多 1 跳；把既有高頻功能往下埋＝UX 退步，需記錄取捨；首頁不放服務市集/加值入口。
客服黑洞 / 壞消息沉默智生活 [已查證]§1.4所有失敗都要具體可行動的錯誤態，不得靜默；error Toast 持久（duration=0）須手動關閉；關鍵流程每分支明示下一步。
宣稱無廣告但仍有廣告（含音效式吸睛）中保好生活 [已查證]§1.1 / §1.4「廣告」定義從寬：任何引導使用者去做與當前任務無關之事的視覺元素皆算（含自家功能促銷、跨賣卡、節慶橫幅、音效動畫）一律禁；只承諾每個畫面可驗證的事。
集點博弈 / 遊戲化參與壓力中保好生活 [已查證+推論]§1.1住戶端不做簽到、連續登入獎勵、點數、徽章、排行榜；禁「看廣告換獎勵」任何變體；紅點/badge 只代表真實待辦數，不製造虛假緊迫感。
過度權限索取且無理由說明中保好生活 [已查證]§1.4權限即時索取 (just-in-time) + 即時說明；支援單張相片選取（不要求完整相簿）；不索取無關權限（MVP 無藍牙需求即不請求）；「已收到回饋」不算修正。
母集團服務當預設入口的跨賣傾向中保好生活 [推論]§1.3 / §1.1MVP 不放任何第三方/集團服務入口；住戶首頁只承載公告/包裹/報修/我的；未來加值須管委會主動開啟、不得擠佔核心動線。
管理端是事後補丁、作業效率差兩家 [推論]§1.2管理端 Web 是專業作業工具，非放大版住戶 App；fold 以上 15–20 列、篩選即時、動作一鍵；管理端零廣告/零加值促銷；狀態顯示精確時間戳。
缺合規稽核 / 「誰看了」可信記錄兩家 [推論]§1.4公告已讀回執以戶號呈現，不顯示住戶姓名；費用催繳一律私訊，禁止公開公告列出欠費戶（個資法 + 信任）。
