系統架構設計 (SASD)

MVP Phase · Backend + Frontend · 2026-06-06
最後更新：2026-06-06（Sprint 1 API 完成；Sprint 2 合約草擬中） ｜  維護人：Lead Architect

架構概覽

Linkju MVP 由兩個獨立服務組成：後端 REST API（linkju-api）與管理員 Web 儀表板（linkju-web）。住戶端使用原生行動 App（iOS/Android）；管理員與主委使用 Web Dashboard（最低 1024px，桌面優先）。

⚙️
Backend — linkju-api
NestJS · Port 3000
  • 框架：NestJS 10 + TypeORM 0.3
  • 資料庫：PostgreSQL 16（主要持久化層）
  • 快取 / 黑名單：Redis 7（ioredis）
  • 推播：Firebase Cloud Messaging (FCM)，最大 500 tokens/批次
  • 檔案儲存：AWS S3 / Cloudflare R2（Presigned URL）
  • 排程：@nestjs/schedule — 公告定時發布（每分鐘掃描）
  • 驗證：passport-jwt + passport-local + class-validator
🖥️
Frontend — linkju-web
Next.js 14 App Router · Manager & Admin Dashboard
  • 框架：Next.js 14（App Router）+ TypeScript
  • 樣式：Tailwind CSS（設計系統 token）
  • 伺服器狀態：SWR（快取、去重、polling）
  • 表單狀態：react-hook-form（無受控重渲染）
  • 編輯器：TipTap（公告富文字，lazy-loaded）
  • HTTP 客戶端：Axios + 401 refresh 攔截器（含並發鎖）
  • 圖示庫：@phosphor-icons/react（按需 import）

資料庫 Schema（11 張資料表）

所有 PK 使用 uuid（gen_random_uuid()）。時間欄位使用 timestamptz。

資料表 用途 關鍵欄位
buildings 社區（租戶）基本資訊，MVP 為單一社區 id, name, address, unit_count, settings (jsonb)
users 所有用戶（住戶、管理員、主委），RBAC 角色欄位 building_id, email, role (ENUM), unit_number, status (ENUM), notification_prefs (jsonb), force_password_change
push_tokens FCM 推播 token，每用戶每平台唯一 user_id, token, platform (ios/android/web)；UNIQUE(user_id, platform)
refresh_tokens JWT Refresh Token 輪替鏈，支援 family 攻擊偵測 user_id, token_hash, family_id, expires_at, revoked_at
packages 包裹到件記錄，含通知狀態追蹤 building_id, resident_id, unit_number (去正規化), carrier, status (PENDING/COLLECTED), notified_at, photo_s3_key
announcements 公告內容，支援草稿 / 排程 / 已發布 / 封存四種狀態 building_id, content_json (TipTap jsonb), priority (NORMAL/URGENT), status (ENUM), scheduled_at, published_at, last_reminded_at
announcement_reads 已讀回執，防止重複寫入 announcement_id, user_id, read_at；UNIQUE(announcement_id, user_id)，INSERT ON CONFLICT DO NOTHING
work_orders 維修工單主表，狀態機流轉 building_id, requester_id, unit_number (去正規化), status (OPEN→ASSIGNED→IN_PROGRESS→RESOLVED→CLOSED), priority, assignee, resolved_at
work_order_photos 工單附圖（S3 key），Cascade 刪除 work_order_id, s3_key, uploaded_by
work_order_status_history 工單狀態變更稽核軌跡，僅新增（Append-only） work_order_id, status, changed_by, comment（RESOLVED 必填）, changed_at
pii_audit_log 個資法合規稽核日誌，5 年保留，僅新增 actor_id, action（USER_SEARCH / READ_RECEIPT_VIEW / PACKAGE_LIST_VIEW 等 11 種）, resource_type, resource_id, ip_address

另有兩張輔助資料表未列入上方計數：invite_tokens（7 天有效期邀請連結）、password_reset_tokens（1 小時有效期，單次使用）。

API Surface（主要端點）

完整端點共 37 個。以下列出各模組最關鍵的端點（約 20 個），說明請求/回應語義。所有需驗證的端點均帶 [JWT]；涉及多租戶隔離的帶 [BG]（BuildingGuard）。

Auth 模組

方法路徑說明
POST /auth/login 登入；bcrypt 驗證；回傳 JWT accessToken（15 分鐘）+ refreshToken（30 天）
POST /auth/refresh Refresh Token 輪替；舊 token 立即作廢；重複使用觸發 family 全數撤銷
GET /auth/me [JWT] 取得當前用戶 profile（含 notificationPrefs）
GET /auth/invite-info 驗證邀請 token 有效性；回傳用戶名稱、戶號、社區名稱；410 表示已過期
POST /auth/register 以邀請 token 完成帳號註冊（設定密碼）；回傳 JWT pair

Buildings & Users 模組

方法路徑說明
POST /users/invite [JWT][BG][MANAGER] 建立 INVITED 用戶 + 邀請連結；需提供 email 或 phone 之一
GET /users/search [JWT][BG][MANAGER] 住戶 Typeahead 搜尋（最少 2 字元）；寫入 USER_SEARCH 稽核日誌；回傳最多 10 筆
PATCH /users/me/push-token [JWT] Upsert FCM 推播 token（ON CONFLICT(user_id, platform) DO UPDATE）
PATCH /users/me/notification-prefs [JWT] 更新推播偏好設定；announcements_urgent 強制為 true，無法關閉

Packages 模組

方法路徑說明
POST /packages [JWT][BG][MANAGER] 記錄包裹到件；同步 FCM 推播住戶；回傳 notified: bool
GET /packages/my [JWT][BG][RESIDENT] 住戶查看自己的待領取包裹（全部）及已領取記錄（最近 30 天）
POST /packages/:id/collected [JWT][BG] 標記已領取；住戶只能操作自己的包裹；409 表示已領取；樂觀鎖防重複
POST /packages/:id/notify [JWT][BG][MANAGER] 補發推播通知；24 小時 rate-limit（429 回應）

Announcements 模組

方法路徑說明
POST /announcements [JWT][BG][MANAGER] 建立公告；PII 關鍵詞檢查（欠費/滯納/未繳/催繳）；可立即發布或排程；FCM 批次推播（最大 500/批次）
POST /announcements/:id/read [JWT][BG][RESIDENT] 標記已讀；冪等操作（INSERT ON CONFLICT DO NOTHING）
GET /announcements/:id/read-receipts [JWT][BG][MANAGER] 已讀回執統計；回傳 unit_number（不含姓名，個資法合規）；寫入 READ_RECEIPT_VIEW 稽核
POST /announcements/:id/remind [JWT][BG][MANAGER] 向未讀住戶補發 FCM；12 小時 rate-limit（429 回應）

Maintenance 模組

方法路徑說明
POST /maintenance [JWT][BG][RESIDENT] 提交維修工單；同步 FCM 推播所有管理員；每住戶最多 5 件未結案（429 超限）
PATCH /maintenance/:id [JWT][BG][MANAGER] 更新工單狀態（狀態機驗證）；RESOLVED 需填說明；FCM 推播住戶（ASSIGNED/IN_PROGRESS/RESOLVED）；422 表示無效轉換

Files 模組

方法路徑說明
POST /files/presigned-url [JWT][BG] 產生 S3 Presigned PUT URL（5 分鐘有效）；filename 伺服器端消毒；S3 key 綁定 building_id；客戶端直接上傳，不經過 API

前端路由架構（App Router）

Web Dashboard 採 Next.js 14 App Router，三個路由群組（Route Groups）：(auth) 公開頁、(manager) 管理員工作台、(admin) 主委稽核視圖。所有 page.tsx 為 Client Component，layout 為 Server Component（渲染 shell HTML，資料由 SWR 在 hydration 後取得）。

    login/
      page.tsx              ← 公開，無需認證

  (manager)/
    layout.tsx              ← AppShell：Sidebar + TopNav；需 MANAGER 角色
    dashboard/page.tsx      ← 總覽統計（待領包裹數、未結工單數、最新公告）
    packages/

關鍵架構決策

多租戶隔離
Multi-tenancy
building_id 嵌入 JWT payload；BuildingGuard 在每次資料存取時驗證 entity.building_id === jwt.building_id。跨社區請求回傳 404（避免暴露資源存在），而非 403。Admin 角色可繞過 building scope。
JWT 認證策略
Auth
Access Token 有效期 15 分鐘；Refresh Token 30 天，採 token rotation（每次使用產生新 token）。舊 token 重用觸發 family 全數撤銷並寫入 Redis 黑名單。登出或帳號停用時即時失效（SADD blacklist:{user_id} jti）。
檔案儲存策略
Storage
二進位資料永不經過 API。API 產生 Presigned PUT URL（5 分鐘有效），客戶端直接上傳至 S3/R2。GET URL 15 分鐘有效。S3 key 格式：buildings/{bid}/{context}/{id}/{filename}，確保多租戶路徑隔離。
推播通知設計
FCM
FCM sendEachForMulticast 最大 500 tokens/批次；失效 token（registration-token-not-registered）自動從 DB 清除。測試環境注入 FakeFcmAdapter（INotificationAdapter 介面），不發出真實推播，可透過 GET /test/notifications/dispatched 查驗。
前端狀態管理
Frontend State
伺服器狀態交由 SWR 管理（快取、去重、焦點重新驗證、polling）；表單狀態使用 react-hook-form（無受控重渲染）；Auth 狀態使用 React Context；UI 暫態（modal open、filter、selected rows）使用元件本地 useState。不引入 Zustand 或 Redux。
個資法合規
Privacy (個資法)
已讀回執僅回傳 unit_number，不含姓名（B-4 決策）。費用催繳類關鍵詞（欠費/滯納/未繳/催繳）在 API 層與 UI 層雙重檢查，觸發警告。所有個資相關操作寫入 pii_audit_log（5 年保留），PiiAuditInterceptor 裝飾器驅動。
公告內容格式
Content
公告正文採 TipTap JSON（content_json jsonb），最大 50KB，在 API 層強制驗證（D-4 決策）。不允許原始 HTML（XSS 風險），前端以 TipTapViewer 渲染，React Native 端以自訂渲染器解析同一 JSON 結構。
分頁策略
Pagination
MVP 採 offset-based pagination（?page=1&limit=25），實作簡單，符合管理員使用情境（按頁瀏覽，非無限捲動）。Cursor-based pagination（適合大資料集或 real-time feed）列為 P1 改進項目。
